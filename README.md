# WoW Teal Types

World of Warcraft API declarations and secret-value checks for Teal addons.
Targets Retail **12.1.5.70575** with the bundled **Teal 0.24.8-wow.1**, generating Lua 5.1 without
compatibility code. Nothing from this package needs to run inside WoW.

## Add to your addon

Place a pinned checkout or extracted package at `vendor/wow-teal-types`.
The development tools support Linux and macOS. Install Go 1.27+ and LuaJIT.
The package includes its pinned compiler. Set `LUA` to use another Lua 5.1
interpreter. A `TL` override must provide the same compiler version and capabilities.

```text
MyAddon/
  src/Main.tl
  MyAddon.toc
  vendor/wow-teal-types/
```

Use a type-only import in `src/Main.tl`:

```teal
local type W = require("wow")

local panel: W.Frame = CreateFrame("Frame")
panel:SetSize(220, 32)
panel:SetPoint("CENTER")
```

The import disappears from generated Lua. Use `local type`, since this package
does not provide a runtime `require("wow")` module.

## Check and build

Run from your addon's directory:

```sh
vendor/wow-teal-types/bin/wow-teal check src
vendor/wow-teal-types/bin/wow-teal build src --output build/lua
```

`check` runs Teal and the additional secret-operation checks. `build` performs
those checks before generating Lua, preserving the directory structure under
`src`. For example, `src/Main.tl` becomes `build/lua/Main.lua`.

Include the generated Lua in your addon package and list it in your TOC. You
own the TOC, assets and installation. Keep build output outside `src`; rebuilds
replace only unchanged output previously generated by this command. Failed
builds preserve the previous output. Serialize builds targeting the same directory.

Select every owned source directory. Imported modules get type checking, but
their bodies get secret-operation checks only when selected. Directory checking
skips declaration files, `.git`, `.venv`, `__pycache__`, `build`, `dist`, `vendor`
and `node_modules`. These subtrees are also hidden from imports unless explicitly
selected or passed as a physical `-I` root. Direct source/include symlinks and
links inside admitted trees are rejected; ancestor aliases are resolved once.

All checks and generation use one bounded copy of the inputs. Changes made after
capture take effect on the next invocation. See [architecture](docs/architecture.md)
for input limits, ownership and recovery behavior.

See [examples/minimal](examples/minimal) for a complete source and TOC example.

## Addon globals and other declarations

Declare your own globals in a file such as `types/my_addon_env.d.tl`:

```teal
global MyAddonCounter: number
```

Then extend the native environment:

```sh
vendor/wow-teal-types/bin/wow-teal check src \
  -I types --global-env-def my_addon_env
```

Pass the same options to `build`. Use additional `-I` arguments for other module
directories. The command ignores ambient `tlconfig.lua` and `TL_PATH`, so supply
your project settings explicitly.

## Secret values

Opaque values can be forwarded to supported native sinks. Inspecting them in
Lua requires access checks; converting them to ordinary scalars also requires
a non-secret result and the expected shape:

```teal
local health = UnitHealth("player")
if canaccessvalue(health) and not issecretvalue(health) and health is number then
   local public_health: number = health
   print(public_health + 1)
end
```

Keep those checks in the consuming function. A cast, a helper's permission check
or a previous getter result does not establish access to the current value.
Plain `tl check` does not enforce all these rules; use the `wow-teal` command.
Values erased through `any` still require runtime care.

Some declarations cover legacy APIs or optional libraries; check availability
before using them. Retain nil guards. Type checking cannot grant protected-call
permission or establish runtime behavior. `--secure` selects secure declarations
without granting native privileges.

See the [declaration contract](docs/api/teal-catalogue.md) for precision limits.
